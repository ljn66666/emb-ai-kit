## 这个项目解决什么问题

「让我的板子接上 AI」这件事，通常死在三个人人都遇到、教程都不写的地方：

1. **电源不够** —— 舵机和主控共用一路 5V。舵机启动瞬间把电压拉塌，ESP32 欠压复位。现象是「一动就重启」。
2. **没有共地** —— 用了两路电源，但 GND 没连在一起。现象是「台面上好好的，装进外壳就开始抖」，串口偶尔乱码。
3. **启动态毛刺** —— 舵机挂在 ESP32 的 strapping 引脚（GPIO0 / 2 / 15）上，上电瞬间被采成启动配置，舵机猛地甩一下。**这个坑固件修不好，只能靠选对引脚。**

另外两个更安静的：I2S 音频的时钟偏斜与 DMA 欠载；以及没有定界的串口协议——丢一个字节，整条链路永久失步。

这五条都在下面这份手册里，每条都配了一分钟验证法。

## 它是什么

三层桥接，职责不能混：

```
┌──────────────┐   带帧串口    ┌──────────────┐  HTTP / stdio  ┌─────────────┐
│   固件层      │ ───────────▶ │   主机桥      │ ────────────▶ │  大模型 / MCP │
│ ESP32 / STM32 │ ◀─────────── │   Python     │ ◀──────────── │ Claude / …   │
└──────────────┘              └──────────────┘                └─────────────┘
```

- **固件层** —— 读传感器、驱动执行器、收发带帧串口。**不持有 API Key。**
- **主机桥** —— 唯一接触 API Key 的一层。把串口事件翻成模型调用，把工具调用翻成串口指令。也可以直接把设备暴露成 MCP 服务。
- **大模型 / MCP** —— 你的模型，通过 MCP 工具驱动硬件。

把 API Key 烧进固件，等于把密钥装进一台会被人拿走的设备。

## 实测硬件

| 元件 | 作用 | 备注 |
|---|---|---|
| Seeed XIAO ESP32S3 Sense | 主控 + 板载麦克风 | D1–D7 用作舵机 PWM |
| MAX98357A | I2S 功放 | BCLK=12, LRCLK=13, DIN=14 |
| SG90 / MG90S / MG996R | 执行器 | **独立 5V 电源，与主控共地** |
| 470 µF 电解电容 | 吸收浪涌 | 跨接在舵机电源 5V 与 GND |

## 目录

| 路径 | 内容 |
|---|---|
| `servo-stabilizer/` | 并发电流预算调度器 + 单元测试。超预算返回 `false`，让调用方下一拍重试 |
| `mcp-device-server/` | 标准库手写的 JSON-RPC 2.0，零第三方依赖。Claude / Cursor 可直接调用 |
| `examples/serial_voice_agent/` | 完整示例：固件 + 主机桥，说一句话让舵机动 |
| `docs/zh-CN/` | 中文实战手册、逐脚接线图、排错对照表 |

## 快速开始

```bash
git clone https://github.com/ljn66666/emb-ai-kit.git
cd emb-ai-kit/examples/serial_voice_agent/firmware
pio run -t upload
```

主机侧：

```bash
cd ../host
pip install -r requirements.txt
python bridge.py --port COM3
```

> 第一次跑，先只接 2 颗舵机。四颗一起上，出问题你分不清是协议、电源还是引脚。

## 没有硬件也能试

```bash
python mcp-device-server/server.py
```

每个工具都会返回 `[simulated]`。用来验证客户端配置是否写对，不会碰串口。
